# ADR-0020: Доставка `manager_url` через константу расширения, опциональные `/C`-параметры

- Статус: `accepted`
- Дата: `2026-04-28`
- Заменяет: первую черновую версию этого же ADR (trait `SessionLaunchParamsCarrier` с `EnvCarrier` / `ParamsFileCarrier` / `CompositeCarrier`).

## Контекст

При обсуждении черновой версии ADR обнаружилось, что предложенная абстракция не покрывает реальные сценарии и переусложняет MVP:

1. **Клиенты, не запускаемые менеджером.** `vanessa_test_client` поднимается изнутри VA‑manager'а; интерактивный 1С‑клиент стартует пользователь руками. Передать им параметры через `Command::env()` или временный JSON невозможно — менеджер их не запускает.
2. **Менеджер на удалённом хосте — обычный сценарий.** Девкаунтейнеры, отдельная VA‑machine, distributed CI. `manager_url` должен браться из конфигурации **внутри 1С**, а не от родительского процесса.
3. **Auth‑token не нужен.** Сценарий — корпоративный dev‑контур, не открытая сеть. «Принимаем любую сессию, что постучалась» — это явно зафиксированная модель доверия (см. §11 спеки в обновлённой редакции).
4. **`kind` клиент знает сам** через `СтрокаЗапуска()`: `/TESTMANAGER` → `vanessa_manager`, `/TESTCLIENT` → `vanessa_test_client`, `/C"...RunYaXUnit..."` → `yaxunit_runner`, иначе — `client`.
5. **Платформа не даёт BSL‑чтение ENV.** Глобальная переменная `ПараметрЗапуска` (StartupParameter) — это строка, переданная через `/C"..."`. Это и есть главный канал доставки от менеджера к клиенту.
6. **Парсер не пишем сами.** В типовой БСП есть готовая обёртка для разбора пар `key=value` из параметра запуска; используем её и в англо‑, и в русскоязычной БСП.

## Решение

Один способ доставки контракта менеджер↔клиент. Никаких trait'ов и реализаций.

### `manager_url` — зашит в клиенте

1. Default `ws://127.0.0.1:4000/sessions` захардкожен в код расширения и совпадает с default‑bind менеджера (§8.3 спеки). Один источник истины.
2. Переопределение — **только** через константу расширения `WebTransportSessionManagerURL`. При первом запуске расширения константа автозаполняется default'ом; пользователь может изменить её через интерфейс ИБ.
3. Параметр `/C"manager_url=..."` менеджер **не передаёт**. Это явно вне контракта: если адрес меняется, его меняют на стороне ИБ один раз, и все 1С‑клиенты этой ИБ видят актуальный адрес.

### Опциональные параметры через `/C"key=value ..."`

Менеджер при `session.spawn` может (но не обязан) добавить в `1cv8c` ключ `/C"..."` со следующим набором:

| Параметр | Когда передавать | Назначение |
|---|---|---|
| `correlation_id` | при спавне менеджером | сквозной trace в логах 1С + менеджер |
| `kind` | редко, как override эвристики | страховка для нестандартных шаблонов запуска |

Других параметров в контракте нет. Auth‑token не передаётся.

Менеджер формирует строку как `/C"correlation_id=<uuid> kind=<kind>"`. Лимит командной строки: Linux — практически без ограничений для нашего объёма; Windows — 32 К символов, наш набор < 200 байт.

### Чтение параметров на стороне 1С (через addin)

Метод addin'а `ПолучитьПараметрыСессии()` возвращает 1С‑коду структуру:

```
{
  manager_url:    String,
  client_uid:     String,   // Новый УникальныйИдентификатор()
  kind:           String,   // вычислен по СтрокаЗапуска() либо из /C"kind=..."
  correlation_id: String?   // только если передан в /C
}
```

Алгоритм:

1. **Парсинг параметра запуска через БСП.** Использовать обёртку из общего модуля БСП `CommonClientServer` / `ОбщегоНазначенияКлиентСервер`. Конкретная функция (имя в типовой БСП, англо‑ и русскоязычная) фиксируется при реализации этапа 5 проверкой против установленной в DRIVE версии БСП. Если подходящего метода в конкретной версии БСП нет — добавляется тонкая утилитарная функция в общий модуль расширения с парой `Имя/Name` (en + ru) — это не «свой парсер», а локальная обёртка над тем же `ПараметрЗапуска`/`StartupParameter` в стиле БСП.
2. **`manager_url`:** только из константы `WebTransportSessionManagerURL`; если константа пуста — fallback на default. `/C"manager_url=..."` игнорируется (даже если кто‑то его передаст).
3. **`client_uid`:** генерируется на стороне 1С через `Новый УникальныйИдентификатор()` / `New UUID()`.
4. **`kind`:** если в `/C"kind=..."` явно задан — используется он; иначе вычисляется по `СтрокаЗапуска()` / `LaunchString()` (поиск `/TESTMANAGER`, `/TESTCLIENT`, `RunYaXUnit`).
5. **`correlation_id`:** напрямую из `/C"correlation_id=..."`; если нет — пустая строка.

Метод вызывается до `session.register`. 1С‑код не различает, спавнили его мы или другой процесс.

### Безопасность

- Загрузка любого 1С‑клиента в реестр менеджера разрешена (модель «доверенный dev‑контур»).
- Bind по умолчанию — loopback. Для случая «менеджер на другом хосте корпоративной сети» — bind на конкретный интерфейс; firewall‑политика — забота инфраструктуры, не контракта менеджера.
- Audit log менеджера фиксирует: `client_uid`, `kind`, заявленный набор tools, источник (PID если известен, иначе только peer address).

## Следствия

### Положительные

- Никакой кросс‑платформенной матрицы доставки. Один путь работает на Linux и Windows одинаково.
- Унифицированный поток для всех типов клиентов: спавненых менеджером, поднятых VA‑manager'ом, запущенных пользователем — все читают `manager_url` из константы.
- Минимум кода в менеджере (`Command::args` без trait'ов и RAII) и минимум кода в addin (одна функция чтения).
- Изменение адреса менеджера — одно место в ИБ, не в каждом скрипте запуска.
- БСП‑совместимо для англо‑ и русскоязычных конфигураций.

### Отрицательные / стоимость

- Расширение `web-transport-addin` теперь обязано регистрировать константу `WebTransportSessionManagerURL` (метаданные + автозаполнение при первом старте) — это часть этапа 5.
- При попытке развернуть расширение на конфигурации без БСП утилитарная функция чтения `ПараметрЗапуска` должна быть в общем модуле расширения (парная en/ru). На MVP этот сценарий не приоритет, но fallback тривиален.
- Точное имя БСП‑метода для парсинга `key=value` пар нужно зафиксировать на этапе 5. До этого момента нельзя зафиксировать сигнатуру `ПолучитьПараметрыСессии()` до байта — только семантику.

### Неграницы

- ADR не описывает auth/TLS политику для не‑loopback bind'а — это отдельный ADR при появлении такого требования.
- ADR не определяет UI редактирования константы — это рутинный экран в подсистеме настроек расширения.
- ADR не покрывает persistence реестра менеджера — см. §1 non‑goals спеки.
