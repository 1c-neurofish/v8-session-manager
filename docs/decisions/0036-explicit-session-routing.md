# ADR-0036: Явная маршрутизация проксированных tools по `session_id`

- Статус: accepted
- Дата: 2026-09-23

## Контекст

После перехода на голые имена tools несколько одновременно активных сессий
с одинаковым `tool_name` обслуживались round-robin. При совместной работе DEV
и production это позволяло вызову без явной цели попасть не в ту базу. При
различающихся схемах имя полностью скрывалось из `tools/list`, хотя каждая
конкретная сессия могла безопасно обработать свой вариант.

## Решение

Публичное имя остаётся `<tool_name>`, отдельный `session.call` не возвращается.
Менеджер добавляет в `inputSchema` зарезервированный аргумент `session_id`:

- один Active-кандидат — аргумент опционален для обратной совместимости;
- несколько Active-кандидатов — аргумент обязателен, вызов без него отклоняется;
- явная цель должна существовать, быть Active и публиковать выбранный tool;
- ошибки цели не запускают fallback и не меняют выбранную сессию;
- перед пересылкой клиенту `session_id` удаляется из `arguments`;
- разные схемы одного имени публикуются через `oneOf`; каждая ветвь содержит
  `session_id.enum`, связанный с зарегистрировавшими эту схему сессиями.

`session_id` становится зарезервированным именем manager-level аргумента и не
может одновременно использоваться клиентским tool как бизнес-параметр.

## Последствия

- Один менеджер безопасно обслуживает DEV и production одновременно.
- Случайный round-robin между базами исключён.
- Существующие вызовы к единственной активной сессии сохраняются.
- `tools/list` отражает реальный принимаемый селектор и конфликтующие схемы.
- Кешовая схема показывает опциональный `session_id`, но без live-сессии не
  обещает допустимое значение; вызов сохраняет ошибку `no_live_session`.
