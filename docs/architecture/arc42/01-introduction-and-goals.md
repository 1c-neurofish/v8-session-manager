## 1. Введение и цели

### 1.1 Назначение

`v8-session-manager` — однобинарный агрегатор клиентских MCP-сессий 1С. Он принимает входящие WebSocket-подключения от 1С-клиентов (через расширение `client_mcp` + транспортный addin) и одновременно экспонирует MCP HTTP (streamable) единым эндпоинтом для AI-агентов и IDE.

Цель: AI-агенту удобно говорить с одной точкой доступа, даже когда за ней живёт несколько подключённых 1С-клиентов (разные базы, разные пользователи, тестовые сеансы).

Менеджер сам 1С не запускает (ADR-0034). Lifecycle `1cv8c` лежит на стороне внешнего оркестратора: deploy-скрипта, IDE-плагина, BSL-расширения прикладной конфигурации.

### 1.2 Заинтересованные стороны

| Стейкхолдер | Интерес |
| --- | --- |
| AI-ассистенты / MCP-клиенты | Стабильный, агрегированный MCP-эндпоинт с предсказуемым именованием тулов |
| Разработчики 1С | Прозрачное подключение `1cv8c` с `mcpMode=ws` к единому менеджеру |
| Авторы прикладных расширений | Возможность публиковать tools из CFE через devkit `client_mcp` без изменений в менеджере |
| Мейнтейнеры | Чёткие модульные границы (`transport`, `registry`, `dispatcher`, `mcp`) |
| Эксплуатация | Запуск под systemd / Windows Service / launchd с минимальным набором настроек |

### 1.3 Цели по качеству

| Приоритет | Цель | Почему это важно |
| --- | --- | --- |
| 1 | Один агрегированный MCP HTTP для агента | Главный пользовательский контракт; агент не должен знать топологию клиентов |
| 2 | Per-session FIFO целостность | Параллельные `tools/call` к одной сессии не должны перетасовываться на стороне 1С |
| 3 | Soft-reconnect при разрывах WS | Тонкий клиент 1С имеет право упасть и переподключиться, не теряя `prefix` и реестр tools |
| 4 | Минимальная публичная поверхность | Только `session_list` + проксированные тулы клиентов (ADR-0034); никакого `session.spawn/kill` |
| 5 | Дешёвая эксплуатация | Один бинарь, один YAML, готовые юниты для systemd/launchd, NSSM-инструкция для Windows |
| 6 | Liveness без application-ping | RFC 6455 Ping/Pong через tokio worker addin'а — не блокирует BSL event-loop |

### 1.4 Область действия

В области действия:

- агрегация WS-сессий 1С-клиентов в один MCP HTTP;
- управление жизненным циклом записей в `SessionRegistry` (register / soft-reconnect / disconnect / idle-sweep);
- per-session FIFO диспетчеризация tool-вызовов;
- дедупликация одинаковых тулов от разных клиентов и резолвинг префиксов;
- bidirectional control plane поверх одного WS (`tools/list_changed` и т.п.).

Не входит:

- запуск 1С-процессов (см. ADR-0034 — менеджер не оркестратор);
- сборка/синтакс/тесты/dump 1С-конфигурации (это было в историческом `v8-runner` CLI, удалено при extraction — ADR-0033);
- удалённый sidecar-аддин для spawn в чужом host'е (ADR-0030/0031 superseded);
- собственное хранилище тулов или скриптов на стороне менеджера.
