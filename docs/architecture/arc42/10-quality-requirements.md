## 10. Требования к качеству

### 10.1 Дерево качества

- Функциональная пригодность
  - агент видит один MCP HTTP-эндпоинт и не знает, сколько 1С-клиентов за ним;
  - имена проксированных тулов стабильны и предсказуемы (`<prefix>__<tool>`);
  - менеджер не пытается имитировать оркестратор: lifecycle 1С — не его зона ответственности.
- Надёжность
  - потеря WS до `reconnection_grace_secs` не убивает сессию;
  - модальный диалог 1С не считается зависанием канала;
  - per-session FIFO исключает race condition внутри одной сессии.
- Производительность
  - WS Ping/Pong обрабатывается в tokio worker addin'а без участия BSL;
  - разные сессии исполняют tool-вызовы параллельно; ограничение — только in-session.
- Сопровождаемость
  - один YAML-конфиг, один бинарь;
  - модули `session_manager/*` строго разделены по ответственности (transport / registry / dispatcher / lifecycle / router / notify);
  - инварианты зафиксированы в `docs/architecture/invariants.md` и в ADR.
- Эксплуатируемость
  - готовый systemd-юнит, NSSM-инструкция, launchd-plist (`docs/INSTALL.md`);
  - graceful shutdown через SIGTERM с настраиваемым grace.

### 10.2 Сценарии качества

| ID | Сценарий | Ожидаемое поведение |
| --- | --- | --- |
| Q-1 | Тонкий клиент 1С теряет WS на 5 секунд и переподключается | Сессия восстанавливается без потери `prefix` и тулов; `generation` инкрементируется. |
| Q-2 | Открыт модальный диалог 1С, BSL event-loop заблокирован на 60 секунд | Канал жив (Pong от tokio worker addin'а), менеджер не сбрасывает сессию. |
| Q-3 | AI-агент кидает 5 параллельных `tools/call` на одну сессию | Они исполняются строго последовательно, в порядке поступления. |
| Q-4 | Два разных клиента публикуют тул с одинаковым `(kind, name, schema_hash)` | Тул появляется в `tools/list` один раз. |
| Q-5 | Два разных клиента публикуют тул с одинаковым `(kind, name)`, но разной схемой | Тул скрывается с предупреждением; ни одна версия не публикуется. |
| Q-6 | Достигнут `mcp.http.max_sessions` | Новый `initialize` получает `503`; существующие сессии работают. |
| Q-7 | Stateful POST без `Mcp-Session-Id` к `/mcp` | Возвращается `400`. |
| Q-8 | SIGTERM во время активного tool-вызова | Менеджер ждёт terminal state до `shutdown_grace_period_secs`, затем завершает процесс. |
| Q-9 | Idle сессия без активности > `idle_timeout_secs` | Idle-sweeper удаляет запись; шлётся `tools/list_changed`. |
| Q-10 | AI-агент пытается вызвать `session.spawn` на менеджере | Тула нет в `tools/list` (ADR-0034); MCP вернёт ошибку «unknown tool». |
